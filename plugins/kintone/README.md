# kintone plugin

Custom rules for developing kintone.
Rules without options are enabled by the `@cybozu/eslint-config/presets/kintone-dev` preset.
Rules that need project-specific options are not enabled by the preset, so import the plugin from `@cybozu/eslint-config/plugins/kintone` and configure them.

## Rules

### `kintone/require-identifier-prefix`

Enabled by the `kintone-dev` preset.

Requires `identifierPrefix` for `createRoot` of `react-dom/client`.
When another React root (e.g. a global navigation in the header) is on the same page, ids generated by `useId` can collide across roots.

Options passed as a variable or a spread are not reported because their contents cannot be inspected.

### `kintone/strict-dependencies`

Not enabled by the preset.

Restricts which files can import a module.
This rule is ported from [eslint-plugin-strict-dependencies](https://github.com/knowledge-work/eslint-plugin-strict-dependencies) 1.3.35 (MIT License, Copyright (c) 2021 Knowledge Work) to work with ESLint 10, and accepts the same options.

```js
// eslint.config.mjs
import kintone from "@cybozu/eslint-config/plugins/kintone";

export default [
  {
    plugins: { kintone },
    rules: {
      "kintone/strict-dependencies": [
        "error",
        [
          {
            // Files under `src/repositories` can be imported only from `src/pages` and the same directory
            module: "src/repositories/**/*",
            allowReferenceFrom: ["src/pages/**/*"],
            allowSameModule: true,
          },
        ],
        { resolveRelativeImport: true },
      ],
    },
  },
];
```

The first option is a list of restrictions. Each restriction has the following properties:

- `module` (required): The import paths to restrict. A glob pattern, or a prefix if it is not a glob.
- `allowReferenceFrom` (required): The files allowed to import the module. Glob patterns or prefixes.
- `allowSameModule`: Allows files that also match `module` to import the module.
- `excludeTypeImportChecks`: Does not report `import type ...`. `import { type ... }` is still reported.
- `targetMembers`: Reports only when one of these names is imported.

The second option is an object with the following properties:

- `resolveRelativeImport`: Resolves relative import paths such as `../foo` before matching them with `module`.
- `pathIndexMap`: For each alias of `compilerOptions.paths`, the index of the path to use. The first path is used by default.

Paths are relative to the working directory of ESLint (`cwd`).
Aliases of `compilerOptions.paths` in `tsconfig.json` in the working directory are replaced with their paths. `extends` is not followed.
The import paths are not looked up in the file system, so a missing extension or `index` is not complemented.
For example, `import "./features/foo"` does not match `src/features/foo/**/*`.

All restrictions whose `module` matches the import path are checked, and the import is reported unless every one of them allows it.
